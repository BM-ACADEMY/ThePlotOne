## 3\. NON-NEGOTIABLE CONSTRAINTS

These are not preferences. If any is implemented in application logic instead of the data layer, it will be sent back.

### 3.1 Lead ownership — the rule the business depends on

leads.campaignId  — IMMUTABLE once set (enforce with a database trigger)

A lead carrying a campaignId can NEVER be matched, offered or assigned

to any project other than that campaign's project.

Enforce with a CHECK/trigger, not an if-statement in a service.

**Why it matters:** if a promoter discovers a buyer generated by his paid campaign was shown someone else's property, the business ends in that town. This must be impossible, not merely disallowed.

### 3.2 One buyer, one agent

UNIQUE constraint: one ACTIVE assignment per leadId

No API path may reveal a buyer's contact to a second agent

No forward, share or transfer function exists anywhere in the product

### 3.3 Quota consumed on ACCEPT, never on OFFER

An expired or declined offer must leave quota untouched. Test this under concurrency.

### 3.4 Campaign is the commercial unit

campaigns \= primary entity (NOT subscriptions with project slots)

one campaign : one project

each campaign has its own committedMinimum, goLive, expiry, pacing, extensions

NOTHING pools between campaigns of the same account

billing aggregates for display only

### 3.5 Server-side authorisation on every endpoint

Hiding a button is not access control. Assume every role will call every endpoint directly.

### 3.6 Audit log is append-only

Every state change: actor, before, after, reason, timestamp. No updates, no deletes. **Ships in Phase 1** — every future dispute is settled from it.

## 5\. TECHNICAL DECISIONS ALREADY MADE

| Decision | Requirement |
| :---- | :---- |
| **PWA, not native apps** | One codebase, no store delays. Native only if retention later demands it |
| **Push (FCM) primary for agents and staff** | Free, instant, no approval. WhatsApp is fallback |
| **WhatsApp for promoters and buyers** | They will never install an app |
| **Push permission mandatory** | An agent cannot activate a paid plan without granting it |
| **Deep links on every notification** | Opens that exact lead. Signed single-use magic link, 24h |
| **Server-time countdowns** | Never trust the client clock |
| **Offline queue** | Agents work from bikes with poor signal |
| **2FA** | Mandatory for super admin and staff |

## 6\. BUILD ORDER — DO NOT REORDER

**Phase 1 (sell-ready).** Auth, roles, OTP, onboarding, push permission · lead intake with source and consent · dedupe · scoring and tiering · **campaign lead lock** · promoter delivery via WhatsApp under 60s · in-house conditional hold · Tier 2 sequential ladder · Tier 1 open offer with masked contact · accept/decline · quota \+ wallet · agent inbox · promoter portal core · super admin leads, subscriptions, alert queue · **audit log**.

**Phase 2 (retention).** Telecaller panel · deal stages and closure reporting · site visit OTP · requirement board · co-brokerage and certificates · threshold alerts · nurture and Friday recycling · validity auto-extension · renewals · multi-city UI · **watchdog, dead-letter queue, orphan detector, daily self-audit**.

**Phase 3 (depth).** Partner and owner portals · finance and GST · page slots · config UI · impersonation · public API.

**Hard gates:** no Phase 2 without the Phase 1 audit log. No Phase 3 without the Phase 2 watchdog. No public launch until all P0 tests in the QA plan pass.

## 8\. WHAT SUCCESS LOOKS LIKE AT PHASE 1

A promoter pays. His campaign goes live within 72 hours. Leads reach his WhatsApp within a minute of arriving. An agent gets a push notification, taps it, accepts, and calls the buyer. Every one of those steps appears in the audit log.

If that works end to end and the P0 tests pass, Phase 1 is done.
